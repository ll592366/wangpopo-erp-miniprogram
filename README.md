# 王婆婆餐饮库存管理系统

> OPC 参赛项目 · 一个人 + AI（WorkBuddy 多智能体 + 微信开发者工具）
> 微信小程序（appid：wx11725297450a489c），微信云开发

## 解决什么问题

餐饮小连锁（1 个总仓 + 3 家门店）的真实痛点：

- 每个店铺的库存老是对不上
- 门店上报食材靠微信群里发消息，容易被顶上去覆盖、看漏漏发
- 配送员还要手动复制粘贴抄单
- 库存信息老板全靠脑子和表格记，信息不可观测

## 系统形态

一个小程序，双端，分账号登录自动路由。**门店只负责经营，一切繁杂的操作交给管理端：**

| 端 | 谁用 | 能干什么 |
|---|---|---|
| 门店端 | 每家店 1 个账号 | 提交食材申请、查看本店库存 |
| 管理端 | 总仓 1 个账号 | 采购入库、确认/驳回门店申请、库存校准、低库存预警、操作日记、数据导出 |

## 核心特性

- 申请单五件套：复制 / 修改 / 确认 / 驳回 / 删除
- 双向库存：总仓 / 门店两套库存，一笔事务结清（总仓减、门店加，要么都成功要么都不动）
- 库存精确到 3 位小数，盘点校准以实数为准
- 防连点锁：14 处写入口全部上锁，连点第二下静默拦截，只出一张单
- 操作日记：谁、几点、干了什么，全部留痕不可改
- 26 个测试套件 1129 条断言全绿，变异测试自证


## 开发方式

一个人 + AI 流水线：AI 产品经理写 PRD → AI 架构师做设计 → AI 工程师写代码 → AI QA 跑测试 → AI 通过微信开发者工具 CLI 部署 → 老板手机真机验收。老板全程零代码，只做三件事：说需求、看结果、拍板。
